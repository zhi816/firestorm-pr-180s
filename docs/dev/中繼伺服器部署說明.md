# 中繼伺服器部署說明（Cloudflare Worker）

> **文件用途**：一步一步把 `worker/` 部署到 Cloudflare，讓其他玩家不必輸入金鑰就能使用 AI 判讀。設計與介面規格見 [實作規格書.md](實作規格書.md) 第七章。
> **適用對象**：倉庫擁有者（Cloudflare 帳號由使用者自行註冊與操作，AI 代理不經手金鑰）。

---

## 一、目前狀態

* Worker 名稱：`firestorm-relay`，網址 `https://firestorm-relay.eddy08160.workers.dev`。2026-11-25 已完成部署：以 Workers Builds 連結 GitHub，每次推送 `main` 自動部署；金鑰 Secret 已設定，`/health` 回 `"ready":true`。
* 前端 `index.html` 的 `RELAY_URL` 指向這個網址的 `/judge`。Worker 故障或金鑰被移除時，遊戲開場探測失敗，自動顯示「離線模式」，不影響遊玩。
* 實測（2026-11-25）：預設模型 `deepseek/deepseek-v4.1-flash-fast` 一次判讀約 6.2 秒，回傳合法 JSON；使用者以手機實玩一局確認可用。

## 二、部署程式碼（擇一）

### 方法 A：連結 GitHub，自動部署（推薦，手機可操作；2026-11-25 已完成連結）

之後每次推送到 `main`，Cloudflare 會自動重新部署，遊戲資料改了也會跟著同步。以下名稱依 2026-11-25 實際後台畫面：

1. Cloudflare 後台進入 **Workers & Pages**，點 `firestorm-relay`，切到 **Settings** 分頁。
2. 往下滑到 **Builds** 區塊，按 **Connect**，依畫面授權 Cloudflare 讀取 GitHub，選 `zhi816` 帳號下的 `firestorm-pr-180s` 倉庫。
3. 建置設定：
   * Production branch：`main`；Disable builds 保持關閉。
   * Build command：留空（`wrangler.toml` 已設定部署前執行 `node build.mjs`）。
   * Deploy command：`npx wrangler deploy`（預設值）。
   * **取消勾選 Enable Preview builds**：否則 AI 代理開的每個分支都會各部署一份測試版並使用同一把金鑰。
   * 點開 **Advanced settings**，**Path 由 `/` 改為 `/worker`**（這就是根目錄設定，一定要改，否則會在倉庫最外層找不到設定檔）。
   * API token 留空（會自動建立部署專用權杖，與 Command Code 金鑰無關）；Variable name／value 留空（那是建置時用的變數，程式執行時讀不到，**不可把金鑰填在這裡**）；Build caching 保持關閉。
4. 按 **Connect**。連結後不會立刻建置，要等 `main` 有新的推送才開始第一次部署；之後可在 **Deployments** 分頁看建置結果。

### 方法 B：在 Mac 終端機部署

於倉庫根目錄執行：

```bash
cd worker
npx wrangler login
npx wrangler deploy
```

`wrangler login` 會開瀏覽器請你登入 Cloudflare 並授權；`wrangler deploy` 會先執行 `node build.mjs`，再把程式部署上去並取代 Hello World。

## 三、設定金鑰（必做，只能由你本人操作）

1. `firestorm-relay` 的 **Settings** 分頁最上方是 **Runtime variables and secrets**（不是 Builds 區塊裡的 Variables and secrets）。
2. 確認選的是 **Production**，按 **+ Add variable**；Type 選 **Secret**（不要選 Text），Name 填 `COMMAND_CODE_API_KEY`，Value 貼上你的 Command Code 金鑰，儲存。
3. 用方法 B 的人也可以改在終端機執行 `npx wrangler secret put COMMAND_CODE_API_KEY`，再貼上金鑰。

金鑰絕不可貼進聊天、寫進任何檔案或提交到 Git。之後重新部署程式碼不會清掉已設定的 Secret。**Bindings** 區塊不用手動新增任何東西，限流用的 Durable Object 由 `wrangler.toml` 在部署時自動建立。

## 四、確認成功

1. 用瀏覽器開 `https://firestorm-relay.eddy08160.workers.dev/health`，看到 `"ready":true` 代表程式與金鑰都到位（`false` 代表還沒設金鑰；看到 `Hello World!` 代表程式還沒部署）。
2. 打開線上遊戲，右上角顯示「AI 模式」，送審後留言與裁判評語是 AI 寫的（不是離線固定句）。
3. 後台 **Observability**（或 Logs）可看到每次判讀的結果代碼與耗時，不會記錄聲明稿內容。

## 五、調整用量上限（選做）

在 **Runtime variables and secrets** 新增類型為 **Text** 的變數即可覆蓋預設值，重新部署不會被蓋掉（`wrangler.toml` 已設 `keep_vars = true`）：

| 變數 | 預設 | 說明 |
| :--- | :--- | :--- |
| `IP_HOURLY_LIMIT` | 30 | 每個 IP 每小時可送審次數。全班連同一個校園 Wi-Fi 時共用對外 IP，課堂展演前建議調高（例如 200） |
| `DAILY_LIMIT` | 300 | 全站每日送審總次數，臺北時間 0 點重置；控制你的 Command Code 額度 |
| `MODEL` | `deepseek/deepseek-v4.1-flash-fast` | 改用其他 Command Code 模型 |
| `ALLOWED_ORIGINS` | `https://zhi816.github.io` | 允許呼叫的網頁來源，逗號分隔；本機 127.0.0.1／localhost 一律放行 |

超過上限時 Worker 回 429，玩家端自動改走離線模式並暫停公用線路 10 分鐘。Cloudflare 免費方案每日 10 萬次請求，遠高於上述上限。

## 六、日後維護

* **改了遊戲資料**（`index.html` 的角色、事件、策略、`SYSTEM_PROMPT` 或 `userPrompt()`）：執行 `node worker/build.mjs` 重新產生 `worker/src/prompt-data.js` 並一起提交。用方法 A 時，Cloudflare 部署前也會自動重新產生；`node worker/build.mjs --check` 可檢查是否同步。
* **換 Worker 網址**（例如在帳號設定改了 workers.dev 子網域）：同步修改 `index.html` 的 `RELAY_URL` 與本文件第一章。
* **想暫停公用線路**：後台刪除 `COMMAND_CODE_API_KEY`，或把 `DAILY_LIMIT` 設為 1；遊戲會自動改走離線模式。
