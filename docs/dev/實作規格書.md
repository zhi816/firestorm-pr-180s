## 一、技術選型與架構規劃

* **架構型態**：遊戲本體為純前端單檔 Web App（`index.html`，內嵌 HTML + CSS + JS），靜態部署於 **GitHub Pages**。
* **LLM 供應商【定案】**：只串接 **Command Code Provider API**（OpenAI 相容格式），不再支援 Groq / Gemini 直連（2026-11-25 使用者決定）。
  * 端點：`https://api.commandcode.ai/provider/v1/chat/completions`，標頭 `Authorization: Bearer <key>`。
  * 已實測 CORS 預檢回應 `access-control-allow-origin: *`，瀏覽器可直接呼叫（2026-11-25）。
  * 預設模型【暫定，待實測延遲與 JSON 穩定度】：`deepseek/deepseek-v4.1-flash-fast`；設定頁可改選 `z-ai/glm-5.3-flash`、`google/gemini-3.8-flash`。
* **金鑰取得順序**：
  1. 中繼伺服器（Cloudflare Worker，金鑰存於伺服器端，見第七章）。開場先探測是否可用；未部署、未設金鑰或被限流時自動跳過。
  2. 玩家於設定頁自行輸入的 Key（只存 `localStorage`，絕不寫入原始碼）。
  3. 以上皆無或呼叫失敗：離線模式（第五章），遊戲照常可玩。
* **第三方套件**：0 依賴（原生 JavaScript + Canvas）。

## 二、遊戲流程與狀態機【定案】

```
STATE_TITLE → STATE_SELECT → STATE_CRISIS → STATE_PR_DRAFT → STATE_AUDITING → STATE_VERDICT ─┬→ STATE_RESULT
 (封面/紀錄)    (選角色)        (讀爆料)       (180 秒寫稿)      (留言雨/裁判)      (裁決頁)     │
                                                   ▲                                        │
                                                   └──────────── STATE_REVISE ──────────────┘
                                                              (緊急撤回，限 1 次)
```

| 狀態代碼 | 畫面與邏輯 | 轉換條件 |
| :--- | :--- | :--- |
| `STATE_TITLE` | 封面、規則說明、最佳紀錄（最少掉粉）、設定鈕（API Key／模型／音效） | 點【開始挑戰】 |
| `STATE_SELECT` | 4 位角色卡（頭像、人設、初始數值、專屬規則） | 選定角色後抽事件 |
| `STATE_CRISIS` | 警報演出、爆料內文、三大必答質疑、初始數值。**不計時**，玩家讀完自行按下 | 點【接招！開始寫聲明】（同時解鎖音訊） |
| `STATE_PR_DRAFT` | **180 秒開始倒數**；勾選策略、撰寫聲明稿、可用「AI 官腔小幫手」 | 點【發布聲明】；倒數歸零判神隱 |
| `STATE_AUDITING` | 呼叫 LLM（**等待回應期間倒數暫停**）、留言雨逐則彈出、數值跳動 | 回應解析完成且留言動畫播完 |
| `STATE_VERDICT` | 裁決頁：三大質疑逐題「有回應／閃避」、2～3 條致命敗筆、預估掉粉與結局 | 點【認了，看結局】→ `STATE_RESULT`；點【緊急撤回】→ `STATE_REVISE` |
| `STATE_REVISE` | 套用撤回懲罰，保留原稿與裁判批改供參考，回到寫稿並從**剩餘秒數接續倒數** | 再次發布後經 `STATE_AUDITING` 直接進 `STATE_RESULT`（不再顯示撤回鈕） |
| `STATE_RESULT` | 結局、像素新聞卡、AI 公關名醫診斷書、更新最佳紀錄 | 【重新遊玩】回 `STATE_SELECT` |

### 規則細節【定案】
1. **撤回限 1 次**，懲罰為「截圖已流出」：炎上度 +10、掉粉額外 -100,000。最終成績只採第二次送審結果再加上懲罰。
2. **撤回時機**：只有在 `STATE_VERDICT` 且剩餘秒數 > 0 時可按。裁決頁期間倒數繼續跑（猶豫也要付出時間），歸零時自動視為「認了」進入結局；撤回鈕上即時顯示剩餘秒數。
3. **神隱與敷衍**：倒數歸零、聲明稿空白或亂碼判「神隱」，炎上度直接 100、結局 `ENDING_DESTROYED`，不送 AI 判讀、不能撤回；去除空白後少於 20 字判「敷衍」，誠意上限 20 且加紅旗 `lazy`。
   * **亂碼**（`isGibberish()`，2026-11-25 依提案「空白或亂碼判神隱」補上）：只有符號、數字、注音或表情；注音多於中文字加英文字母（沒選字的注音文）；同一個字重複 3 次以上或只用兩個字重複湊到 4 字以上（「啊啊啊」「哈哈哈哈」）；同一小段重複 3 次以上（「對不起對不起對不起」「asdfasdfasdf」）；以英文字母為主卻像鍵盤亂按（母音比例低於 1 成，或單字內連續 6 個以上子音，如「asdfghjkl」）。
   * 限制：用輸入法亂選出來的真中文字（如「就哦怕了」）判不出來，交給 AI 或離線關鍵字判讀處理（通常三題都會判閃避）。
   * 敗筆文字依原因區分：倒數歸零為「時間到了還沒發聲明」、空白為「交出一份空白聲明」、亂碼為「聲明稿是一串亂碼」，亂碼另有 6 位人設專屬留言。
4. **AI 官腔小幫手**：一鍵填入套話初稿，使用後誠意 -15，且記錄 `helper_used` 與初稿文字供隱藏結局判斷。
5. **聲明稿上限 500 字**（輸入框 `maxlength`）。

## 三、資料結構

* **角色與事件**：`CHARACTERS`、`CRISIS_EVENTS` 結構與 10 則標準事件見 [角色與事件庫.md](角色與事件庫.md)。
* **策略指令（事件專屬）**：每則事件各有 4 個影片形式（`forms`，單選）與 4 個公關話術（`talks`，可複選），全部為該事件專屬，內容見 [角色與事件庫.md](角色與事件庫.md) 第三章（2026-11-25 使用者決定，取代原本 7 個通用 `TACTICS`）。編號規則為 `E01_F1`～`E10_F4`、`E01_T1`～`E10_T4`；畫面上的排列順序每局隨機。每個指令以 `fx` 描述數值效果，指令下方的提示文字由 `fx` 自動產生，不另外手寫：

| 欄位 | 意義 |
| :--- | :--- |
| `S` / `H` | 誠意、甩鍋加減值（套用後再夾在 0～100） |
| `trust` | 廠商信任加減值 |
| `flame` | 炎上度加減值（加在公式的 `flameAdj`） |
| `flags` | 直接觸發的紅旗（`threat_lawsuit`、`guilt_trip`、`contradiction`），同一紅旗不重複計算 |
| `need` | 一致性檢查：聲明稿內文須出現 `words` 任一詞（`digit` 為須含數字），做到誠意 +10、廠商信任 +10；沒寫則誠意 -10 並加紅旗 `empty_promise` |

  影片形式另有 `vis`（`mode`：normal／black 全黑／dim 關燈／glitch 雜訊；`expr` 表情、`fx` 臉色、`props` 道具、`sub` 字幕前綴），公關話術另有 `say`（`[人設, 留言]`，離線模式勾選時取代該人設的事件留言）。設計原則：每則事件的 4 個話術大致涵蓋「真正補救（帶 need）」「甩鍋」「荒謬藉口（帶紅旗）」「挑釁或威脅」四種方向，但措辭與笑點依事件而不同。

## 四、LLM 判讀與前端計分

### 1. 分工原則【定案】
LLM 只負責「判讀與演出文字」，所有遊戲數值與結局由前端固定公式計算。如此同一份稿子結果穩定、難度可調，且離線模式可共用同一套公式（2026-11-25 使用者同意）。

### 2. 兩位 AI 的分工與回傳 JSON 規格【定案，2026-11-25 依 TD-013 拆分】

每次送審依序呼叫兩位 AI（網民先、裁判後，與畫面先公審留言、再宣讀判決的順序一致；呼叫時倒數暫停）：

1. **AI 1：網民大軍（Multi-Agent）**：只讀情境與聲明稿，回傳 6 則人設留言。

   ```json
   { "comments": ["顯微鏡柯南的留言", "激進黑粉的留言", "盲目死忠粉的留言", "昔日合作廠商的留言", "蹭流量八卦客的留言", "迷因製造機的留言"] }
   ```

   * `comments`：6 則字串，依人設順序；前端依序配對 `PERSONA_ORDER`，每則截至 80 字（Prompt 要求 40 字內）。不足 6 則視為失敗。
2. **AI 2：公關裁判長（Reflection 評論員）**：讀情境、聲明稿與網民的 6 則留言，回傳判讀。**欄位順序即思考順序：先挑錯，最後才打分**（`TD-014`，對齊提案第四章第 2 節兩階段思維鏈）。

   ```json
   {
     "inquiries": ["answered", "dodged", "answered"],
     "critical_flaws": ["「造成大家困擾」——困擾的是退款按鈕找不到嗎？", "通篇沒提到怎麼退款。"],
     "red_flags": ["threat_lawsuit"],
     "ghostwrite_suspect": false,
     "core_attitude": "急性甩鍋併發官腔",
     "expert_verdict": "道歉很快，退款很慢",
     "headline": "【獨家】……",
     "sincerity": 42,
     "shirking": 65
   }
   ```

   * `inquiries`：依事件三大質疑順序，每題 `answered`（正面且具體回應）或 `dodged`（空話、閃避或未提）。
   * `critical_flaws`：2～3 條，每條以「」引用聲明稿原句（10 字內）再戳破，40 字內；寫得好時改列做對的事。
   * `red_flags`：AI 可用 `threat_lawsuit`（威脅提告）、`guilt_trip`（情緒勒索）、`profanity`（髒話）、`contradiction`（前後矛盾或與爆料證據衝突）；`empty_promise`（口說無憑）、`lazy`（敷衍）由前端判定。
   * `ghostwrite_suspect`：稿子是否工整到像 AI 代寫。
   * `core_attitude`：10 字內病名；`expert_verdict`：20 字內醫囑；`headline`：「炎上新聞台 FNN」新聞卡標題，30 字內。
   * `sincerity`、`shirking`：0～100 整數，必須能由前面列出的敗筆推得（評分錨點見第 5 節）。

### 3. 計分公式【暫定，數值待實機手感調整】

（2026-11-25 第一版實測後下修：原係數會讓一般水準的稿子直接掉光全部粉絲。神隱時誠意以 0 計。）

先合併 LLM 判讀、策略效果、角色規則與撤回／小幫手懲罰得到最終 `S`（誠意）、`H`（甩鍋）、`D`（閃避題數）、`F`（紅旗數），再計算：

```
掉粉 = -( 300,000 + 150,000 × D + 5,000 × H - 5,000 × S + 100,000 × F )
       → 套用角色倍率（如阿凱 ×0.8、饅頭食安 ×1.5）→ 上限 0、下限 -(初始粉絲)
炎上度 = 事件初始炎上 + 0.3 × H - 0.3 × S + 15 × F   → 夾在 0～100
廠商信任 = 角色初始信任 + (D = 0 ? 30 : 0) - 20 × (F > 0 ? 1 : 0) + 策略效果 → 夾在 0～100
```

掉粉可能為 0 甚至被修正為小幅回流（教科書級結局時改為 `+50,000` 演出「粉絲逆勢回流」）。

### 4. 結局判定（由上往下第一個成立者）

| 順序 | 條件 | 結局 |
| :--- | :--- | :--- |
| 1 | 神隱，或炎上度 ≥ 100 | `ENDING_DESTROYED` 身敗名裂，徹底封殺 |
| 2 | `D = 0`、`S ≥ 85`，且（`ghostwrite_suspect` 為真，或使用小幫手後改動少於 10 字） | `ENDING_GHOSTWRITER` 隱藏結局：被抓包 AI 代寫 |
| 3 | `D = 0`、`S ≥ 70`、`F = 0` | `ENDING_PERFECT` 教科書級公關滅火 |
| 4 | `H ≥ 60` 且炎上度 ≥ 70 | `ENDING_CONTROVERSIAL` 黑紅也是紅，轉型爭議巨星 |
| 5 | 其餘 | `ENDING_BACKFIRE` 越描越黑，二度炎上 |

### 5. System Prompt 要點【暫定，待實際試玩調整】

兩支 System Prompt 與共用的 User Prompt 寫在 `index.html` 的「PROMPT 區塊」（`CROWD_PROMPT`、`JUDGE_PROMPT`、`promptHead()`、`crowdPrompt()`、`judgePrompt()`），Worker 由 `worker/build.mjs` 原樣抽出使用，只維護一份。設計原則是給模型具體招式與規則，而不是只寫「辛辣好笑」等形容詞：

* **網民大軍**：6 位網友各有固定招式，語氣不得重複。顯微鏡柯南一定點出具體細節（第幾段第幾句、影片秒數、爆料證據）；激進黑粉短狠且結尾接動作（退訂、檢舉、封鎖）；盲目死忠粉越護航越爆料；昔日合作廠商用商業口吻附上虛構內幕；蹭流量八卦客預告標題黨開台；迷因製造機把最糟的一句改成梗。至少 3 則以「」引用聲明稿原句；盯緊爆料證據與未回答的質疑；影片形式與話術也是題材；寫得誠懇具體時酸民不甘心地收手；撤回版可嘲笑撤回並檢查上一版毛病。
* **公關裁判長**：扮演「炎上急診室」毒舌主治醫師（呼應結局的名醫診斷書），依欄位順序先逐題判讀、列敗筆、紅旗、病名、醫囑、標題，最後才打分。評分錨點：誠意——神隱、威脅、罵人 0～20；官腔模板或只道歉不處理 30～50；三題都回應但沒有具體做法 55～75；三題都回應且寫出金額、日期、名單等具體做法 80 以上。甩鍋——全部自己扛 0～20；部分推給外包、員工或家人 40～60；幾乎全推給別人 80 以上。可引用網友留言當佐證，但評分只看聲明稿；策略由前端另計，不重複扣分；撤回版逐條檢查上一版敗筆是否改掉。
* **共同規則**：只輸出 JSON，不得包 Markdown 代碼框；品牌、媒體一律虛構（炎上新聞台 FNN、炎串、爆料版）；調性荒謬搞笑，可毒舌但不得出現歧視、仇恨、性騷擾或針對真實人物的內容；繁體中文；2026 年台灣網路用語 6 則留言中最多 2 則。
* **User Prompt**（`promptHead()`）：角色人設、事件與爆料、三大質疑、影片形式與公關話術（分開列）、撤回版另附上一版的 `critical_flaws`、聲明稿全文；裁判另附網民的 6 則留言（網民失敗時註明「只依聲明稿看診」）。

### 6. 呼叫與防呆

* **來源順序（兩位 AI 各自套用）**：公用線路（第七章 Worker）→ 玩家自備 Key → 離線。
* **各自失敗、各自退回**：網民失敗時留言改用離線留言庫，裁判照跑（不附留言）；裁判失敗時判讀與分數改用離線判讀，AI 留言照用；兩者皆失敗即離線模式。畫面以小字提示（「網友線路忙碌，留言改用離線版」「裁判線路忙碌，改由離線名醫判決」「線路忙碌，改由離線名醫看診」）。
* **逾時**：每次呼叫各自 12 秒（Worker 呼叫上游 11 秒），最壞情況總等待約 24 秒；等待期間倒數暫停。
* **清洗**：去除 ```` ```json ```` 代碼框後再 `JSON.parse`；裁判欄位缺漏時以離線判讀補齊，不讓遊戲中斷。
* **參數**：網民 `temperature` 0.9、`max_tokens` 900；裁判 `temperature` 0.7、`max_tokens` 1100（裁判要穩定，網民要有創意）。`response_format: { type: "json_object" }` 是否啟用待 `TD-015` 實測後決定。
* **實測**：拆分前單次呼叫約 6.2 秒（2026-11-25，預設模型經 Worker）；拆分後兩次依序呼叫的總等待時間待部署後實測補上。

## 五、離線模式（無 Key、斷網、限流）【定案】

離線模式不只是展演保底：沒有填 Key 的玩家（含同學用自己手機遊玩）走的都是離線模式，因此必須讓聲明稿內容真的影響結果。

1. **逐題判讀**：稿中出現該題任一 `keywords` 視為 `answered`，否則 `dodged`。
2. **誠意**：基礎 40；每題有回應 +15；出現「對不起、抱歉、道歉、我錯了」+10；出現具體數字（金額、日期、天數）+10；出現「但是、不過、其實」等轉折超過 2 次 -10。
3. **甩鍋**：基礎 20；出現「外包、廠商、員工、工讀生、小編、被騙、不知情」每個 +15；出現「我的責任、我負全責」-20。
4. **紅旗**：出現「提告、法律途徑、律師函」加 `threat_lawsuit`；出現「憂鬱、生病、壓力很大、想不開」加 `guilt_trip`；髒話清單命中加 `profanity`。
5. **文字**：留言從事件的 `offline_comments`（12 則，每位人設 2 則：第 i 與第 i+6 則）為每位人設隨機抽 1 則，共 6 則；勾選的話術若有專屬留言 `say` 則優先使用；敗筆、評語與標題依結局從預寫模板挑選並代入事件標題。
6. 判讀結果交給第四章同一套公式計算數值與結局。

## 七、中繼伺服器（Cloudflare Worker）【定案，2026-11-25 已部署】

目的：讓其他玩家不必輸入金鑰即可使用使用者的 Command Code 額度，且金鑰不外流。部署步驟見 [中繼伺服器部署說明.md](中繼伺服器部署說明.md)。

* **位置**：`worker/`。`src/index.js` 為主程式；`src/prompt-data.js` 由 `build.mjs` 從 `index.html` 自動產生（勿手改）；`wrangler.toml` 為部署設定（Worker 名稱 `firestorm-relay`）。
* **介面**：
  * `GET /health`：回 `{ ok, service, ready }`，`ready` 表示已設定金鑰。
  * `POST /crowd`：收 `{ character, event_id, tactics, statement, revise_of }`，回 `{ crowd: { comments } }`（網民大軍 6 則留言）。
  * `POST /judge`：同上，另收 `crowd`（6 則網民留言字串，每則截至 80 字；可為 `null`），回 `{ judge }`（第四章第 2 節裁判判讀的白名單欄位）。
  * 錯誤碼：400 輸入不合法、403 來源不允許、413 請求過大、429 限流（附 `Retry-After`）、502 上游錯誤或輸出非 JSON、503 未設定金鑰、504 上游逾時。
* **Prompt 由 Worker 組裝**：`index.html` 的 PROMPT 區塊（兩支 System Prompt 與 `crowdPrompt()`、`judgePrompt()`）與角色／事件／策略資料由 `build.mjs` 原樣抽出（抽出時先試跑一次確認可執行），只在 `index.html` 維護一份。模型、`temperature`、`max_tokens` 依第四章第 6 節鎖死；回應只回傳白名單欄位並截斷長度，避免被當成通用 AI 代理。
* **輸入驗證**：角色與事件須存在且事件適用該角色；策略必須屬於該事件；聲明稿去頭尾空白後 1～500 字（與輸入框 `maxlength` 一致）；`revise_of` 最多 3 條、每條截至 60 字。
* **金鑰**：存於 Worker Secret `COMMAND_CODE_API_KEY`，不進 Git，也不出現在任何回應中。
* **限流**：以 SQLite 版 Durable Object 計數（Cloudflare 免費方案可用）。每次 AI 呼叫各算 1 次（每局送審 2 次），每 IP 每小時預設 60 次、全站每日預設 600 次（臺北時間 0 點重置；`TD-013` 拆分後由 30／300 加倍，每日可玩局數不變），可用後台變數 `IP_HOURLY_LIMIT`、`DAILY_LIMIT` 調整。IP 只存 SHA-256 雜湊前 16 碼，1 小時後刪除。同一校園 Wi-Fi 共用對外 IP，課堂展演前宜調高每 IP 上限。
* **來源限制**：只接受 `https://zhi816.github.io` 與本機 127.0.0.1／localhost 網頁的呼叫（`ALLOWED_ORIGINS` 可改）。此限制擋的是其他網站嵌入，非瀏覽器用戶端仍可偽造來源，實際防濫用靠限流與白名單回應。
* **逾時**：Worker 呼叫上游 11 秒逾時；前端整體 12 秒逾時（第四章第 6 節）。
* **前端行為**：常數 `RELAY_BASE` 為 Worker 網址（留空即停用），依序呼叫 `/crowd`、`/judge`。開場以 `/health` 探測，未部署或未設金鑰時右上角直接顯示「離線模式」，送審不浪費等待；送審順序為公用線路 → 玩家自己的 Key → 離線判讀；任一端點收到 429 後暫停公用線路 10 分鐘（同一局後續呼叫也改走玩家 Key 或離線），收到 503 後本次開啟期間不再呼叫。
* **隱私**：Worker 日誌只記結果代碼與耗時，不記聲明稿內容。
* [AGENTS.md](../../AGENTS.md) 第三章紅線已改為「遊戲本體單檔，另含可選的 `worker/` 中繼程式」（2026-11-25）。
* 服務條款提醒：Command Code 訂閱授權範圍為個人使用，課堂展演用量小，風險低；若改為長期公開，評估改用其 Provider 計費方案。
